# 可选模块：对话式设定构建（Setting Builder）

> 本模块是 human-like-novel 的**可选前置模块**——开书前通过对话式引导，从作者脑中结构化地「问」出翔实设定库，而不是让作者写长文档、也不是边写边补。
>
> **启用**：长篇网文（目标 ≥50 万字）、需要完整世界观、愿意以对话方式构建设定。
> **跳过**：短篇、快节奏开书、作者偏好边写边定、环境不支持对话式工作流。
> 本模块纯对话 + 落盘实现，**不依赖任何平台特性**；不启用时完全不干扰原有写作流程。

---

## 一、为什么需要这个模块（背景）

长篇连载的逻辑错误、前后矛盾，根因常在**设定库从源头欠账**：

- 作者开工时只有梗概，设定是**边写边补**——写到某处才临时定规则，前后难免打架；
- 设定库**量级不足**：正文需要的约束密度 > 设定提供的密度，模型生成时无据可依，只能自造（自造即出错）；
- 设定是**散文式长文档**，一读全读，关键约束被稀释成噪音，生成时抓不住。

实测参照：某长篇目标 350 万字，设定集断断续续补到 14 万字（≈目标 1/25），正文仍反复出现时间线/口径/位置类硬伤——**设定量级不达标**。据此定达标线：**设定集 ≥ 全书目标字数 × 1/10**（目标 350 万 → 设定 ≥35 万字；目标 100 万 → ≥10 万字）。此线为初版标准，可按体裁微调（脑洞文可略低、考据文应更高），但**低于 1/20 视为严重欠账**。

---

## 二、核心流程

```
前置：确定目标字数 → 计算达标线（目标 ÷ 10）
  ↓
对话引导（七阶段，顺序执行）
  每阶段：引导问题模板 → 逐问作答 → 盲区追问 → 结果落盘
  ↓
双标准检查（每阶段结束 + 全部结束各一次）
  标准A 背景完善度：本阶段检查单逐项勾完，缺项当场追问
  标准B 设定量级：落盘累计字数 ≥ 达标线
  ↓
输出结构化设定库（yaml：实体 / 关系 / 约束）
  ↓
进入正常写作流程（每章按核心实体查询注入包）
```

**对话纪律**（执行本模块时遵循）：
- 一次只问一个问题，等作者答完再问下一个；不连续轰炸。
- 作者回答发散时，先记下再归位到对应主题；不打断思路。
- 作者说「没想过/你定」时，给出 2-3 个候选方案让其选，**不得擅自拍板 canon**（设定权在作者）。
- 每答完 5-8 问，回显一次已落盘要点，让作者确认有无记错。
- 全程把作者原话中的专名、口径原样保留，不擅自改写。

## 三、七阶段引导

### Phase 0 · 书核（整本书的锚点）

**目的**：锁定卖点/类型/读者/目标字数——目标字数决定达标线的绝对值。

引导问题：
1. 一句话说清这本书的卖点（读者为什么看它）？
2. 类型细分？（如「修真+规则辩论」「都市+系统+扮猪吃虎」）
3. 目标读者画像？（年龄/口味/前作偏好）
4. **全书目标字数**（决定设定达标线）？
5. 和同类型头部作品比，差异化在哪（一句话）？
6. 核心爽点/情绪基调？（打脸？逆袭？烧脑？治愈？）
7. 结尾大方向定了吗（一句话，可不剧透细节）？

**检查单**：卖点□ 类型□ 读者□ 目标字数□ 差异化□ 爽点□ 结局方向□
**落盘**：书核卡片（含达标线计算）。

---

### Phase 1 · 世界观（背景完善度重点）

**目的**：世界是否「立得住」——本阶段决定背景完善度，投入产出比最高。

引导问题（分主题）：
- **顶层规则**：世界的基本运行规则？有没有天道/法则/系统/神这类顶层存在？它管什么、不管什么？
- **力量来源**：力量从哪来？（灵气/血脉/信仰/知识/科技/位格）凡人能获取吗？代价？
- **历史时间线**：世界存在多少年？分几个纪元/时代？发生过哪些大事？（至少 3 个锚点事件）
- **地理版图**：几个区域/大陆/界域？各自特色？交通与隔绝？
- **势力格局**：几大势力？实力排序？资源分布？明暗关系？
- **经济体系**：货币？硬通货？贸易路线？贫富结构？宗门/国家靠什么运转？
- **文化习俗**：语言？信仰？节日？禁忌？婚丧？阶层礼仪？
- **凡俗 vs 超凡**：凡人和修者/超凡者的关系？凡人怎么看待超凡？
- **世界边界**：世界有界还是无限？边界外有什么（若有）？
- **力量对社会的影响**：超凡力量怎么塑造政治/经济/法律？

**检查单**：顶层规则□ 力量来源□ 历史3锚点□ 地理□ 势力□ 经济□ 文化□ 凡俗关系□ 世界边界□ 力量×社会□
**盲区追问**（作者答完后的常见缺口）：世界观里最容易漏的是「经济怎么运转」和「凡人视角」——主动追问。

---

### Phase 2 · 人物网

引导问题：
- **主角**：出身/当前处境/性格锚点（3 个）/目标（表层+深层）/致命弱点/金手指（能力+边界+代价）/黑历史或心结/说话习惯（可选）
- **关键配角**（3-5 个）：身份/与主角关系/立场/动态（会怎么变）
- **反派**（1-3 个）：动机（可共情吗）/实力/与主角的冲突线/会不会洗白
- **女主/感情线**（若有）：相遇方式/关系节奏/感情阻碍
- **人物关系网**：谁欠谁/谁恨谁/谁保护谁（一张关系图）

**检查单**：主角8项□ 配角3+□ 反派动机□ 关系网□
**盲区追问**：反派的动机最容易被写成「就是坏」——追问到「他为什么认为自己对」。

---

### Phase 3 · 能力体系（逻辑矛盾高发区）

引导问题：
1. 等级框架？（名称/数量/天花板——炼气筑基金丹？还是别的体系）
2. 升级路径？（修炼/吞噬/系统任务/位格提升）
3. **能力的边界**：能做什么，**不能做什么**？（边界比能力本身更重要）
4. 代价/限制？（透支？反噬？寿命？）
5. 克制关系？（什么克什么）
6. 能力获取有门槛吗？人人都能修吗？
7. 能力与社会地位/权力的关系？

**检查单**：等级框架□ 升级路径□ 边界□ 代价□ 克制□ 门槛□ 能力×社会□
**盲区追问**：「新手期主角不能做什么」必须明确——这是前期剧情不崩的根。

---

### Phase 4 · 剧情结构

引导问题：
1. 主线一句话？
2. 分卷规划：几卷？每卷的起承转合？（可只定前 2-3 卷）
3. 单元案/支线池：至少 5 个可写的独立事件？
4. 卷间钩子：每卷结尾留下什么悬念？
5. 大高潮安排在哪？
6. 主角成长线：开局能力 → 结局能力的路径？

**检查单**：主线□ 分卷□ 支线池5+□ 卷间钩子□ 高潮□ 成长线□

---

### Phase 5 · 专名与口径（防跨章不一致的根）

引导问题/动作：
1. **全量专名表**：人名/地名/机构/功法/物件的规范写法（含同音近形易混的标注）。
2. **硬约束口径**：哪些设定**绝对不能写错**？（如「某池主效洗髓、对某封算不得对症」这类——每条口径都记录「正确表述」）
3. **禁用表达**：哪些词/说法全书禁用？（敏感词、不合身份的称呼、易被误读的表述）
4. **易混淆点**：哪些设定读者/作者容易混？（两个宗门？两个印？同名人？）
5. 动态状态锚点：到第几章时谁是什么状态？（如「某角色第 N 章前未出场」「某能力第 N 章才解锁」）

**检查单**：专名表□ 硬约束口径□ 禁用表达□ 易混点□ 状态锚点□
**盲区追问**：专名表一定要问「有没有两个字长得像/读音像的」——跨章写错专名是高发错误。

---

### Phase 6 · 平台红线（合规框架）

引导问题：
1. 题材是否涉及现实机构/职业？（律师/警察/医生/法官）→ 是否架空化处理？
2. 暴力/情色边界定在哪？
3. 敏感历史/政治指涉有没有？（避免直接映射）
4. 未成年人相关设定是否合规？

**检查单**：现实指涉架空化□ 暴力情色边界□ 敏感史政□ 未成年合规□

---

## 四、双标准检查（翔实度验收）

**标准 A · 背景完善度**：以上每阶段检查单全部勾完。任一缺项 = 未完成，回到该阶段追问补齐。
**标准 B · 设定量级**：落盘累计字数 ≥ 目标字数 × 1/10。未达标 = 继续扩写——优先扩世界观（Phase 1）和剧情池（Phase 4），因为这两块最「胀」字数且最有用。

验收输出：一张达标单（阶段✓ + 量级：当前 X 万字 / 达标线 Y 万字）。

---

## 五、落盘与输出（主形态=每书独立图数据库）

**核心原则**：设定以**图数据库**为唯一真源（组织形式=节点+关系边，按需取关联子图，杜绝「文档一读全读」的噪音稀释）；md 仅作**对话日志/人类可读视图**（非最终产物）。

- **每书一库**：`<项目>/.memory-graph/memory.axeb`（axolotl 图库，经 lobster-memory runner 操作，库路径由 `LOBSTER_MEMORY_DIR` 指定——不同书用不同目录即隔离）。
- **写入方式**：节点 = 实体/机制/人物（id/label/content/weight），边 = 关系（from/to/kind，kind 用枚举 relates_to/caused/part_of/feedback/derived，具体语义写入边 content）。domain 用 `knowledge`（引擎枚举仅 emotion/knowledge/task，书设定归 knowledge；如需专属 book 域，改引擎 `schema.py` 的 VALID_DOMAINS——小改动，作者定）。
- **对话日志**：每阶段一文件（md），保留作者原话，作为图的旁证与可读快照。
- **查询注入**：每章开写前，`recall <本章核心实体关键词>` 取关联子图 → 组装注入包（该实体状态 + 绑定约束 + 关联事件 + 待接钩子，1-3 千字）——设定全保留在图里，只注入相关子集。

---

## 六、模块边界

- **设定权在作者**：本模块只负责「问」和「整理」，所有 canon 由作者拍板；作者说「你定」时才给候选，不擅自定案。
- **不替代写作流程**：本模块产出的设定库，供写作时查询注入；写作纪律（文风/机检/防复发）仍走 human-like-novel 主流程。
- **量级是手段不是目的**：1/10 是保底线，达标即止；若作者在达标前已对世界观/人物有完整把握，可经作者确认提前收尾（作者说「够了」就是够了）。
