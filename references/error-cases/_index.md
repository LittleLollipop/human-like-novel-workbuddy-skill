# 实战错误案例库 · 索引（118 条）

## 原库说明（持续累积）

本文件累积**真实写作中暴露的文风/设定问题**，作为技能的经验库。每条案例都来自实际项目反馈，包含「现象 → 根因 → 错误写法 → 正确写法 → 可固化规则」，供后续创作前对照规避。案例中的人名、地名、专有机制均为**脱敏后的通用占位**（主角 / 某角色 / 某镇 / 某宗门 / 某符号），便于套用到任意作品。

> **如何新增案例**：在遇到新的、可复用的文风/设定问题时，复制文末「案例模板」追加到本文件，编号顺延（#001、#002…）。每条力求简短（错误/正确片段各 ≤150 字），便于快速扫描。

> **⚠️ 机检闭环纪律（最高优先，来自 2026-07-17 某章–11 复检教训）**：每次重写/修改正文后，必须对本章跑**一遍覆盖全部可机检模式的完整扫描**，不能只跑「字数 + 说·道 + 禁词 + 相邻重复」这四项基础 QC。本次 某章–11 复检即因缺全扫，漏掉 某章 整章 136 个 ASCII 英文引号（自检报告还假称「引号统一「」」）与 7 处 #023「一X」突发词残留。可机检模式至少含：破折号数（≤3）、引号规范（本书用「」/『』，禁 ASCII 引号）、一X/名词一动词突发词、X了一分族、否定式（不X不Y/像在X/防御性不是X）、前世类词、旧名残留。各项目应自备扫描脚本（如 scan_errors.py），写后必跑，假阳性手动甄别，真违规即修。


> **本库已拆分**：每条详情见对应分类文件（`cat-*.md`）。查章流程见下方「使用流程」。新增案例复制 `_template.md` 并顺延编号，同时在本索引追加一行。


## 使用流程（防漏查）

1. **先读本索引**（一眼看全 111 条，不可能 silently 漏掉）。
2. **跑技能通用运行器** `check_error_cases.py <章节文件>` → 自动扫通用机检项（#020/#023，#024 亦覆盖）。
3. **跑项目脚本** `.check_chapter.py <章节文件>` → 扫项目级项（#007 某线亮起/#060 现代词 禁词、说·道、字数、破折号等）。
4. **对索引中「人工」项**，按分类文件逐条对照本章；「项目」项以项目脚本结果为准。
