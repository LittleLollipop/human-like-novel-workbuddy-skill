# 错误案例 · 节奏/信息交代

## 案例 #014 — 避免过量内心独白/心理推演（"小说要故事，不是主角怎么想"）

- **来源**：用户长篇连载项目反馈（修真+规则辩论题材，2026-07-15）
- **现象**：叙述靠主角的"想"推进。用户原话：「太多的心理活动也不对，小说要的是故事，不是主角怎么想怎么想之类的」。典型症状：用「在心里分作两处：一桩已了，一桩才开头」「把那一幕在心里反复嚼……（长段推理）……这某域的因果，往后每亮一分，对面的改，便多一分忌惮」「心头微动，他想……忽觉肩上沉了些，他不知这担子要扛多久，只知道……」等长段内心分梳/推演当叙述发动机。读者读到的是主角的大脑运转，不是事件在发生。
- **根因**：把"交代主角思路"误当成"推进故事"。小说靠**故事**（动作、对话、事态、他人反应）往前走，内心活动只是其中一味调料，不是主菜；一旦用"主角想 X、想 Y、得出结论 Z"替代"事发生"，故事就停了。
- **错误写法（片段）**：
  > 他把那桩刚在某宗门了却的冤案，和这桩刚接下的麻烦，在心里分作两处：一桩已了，一桩才开头。（纯内心分梳，零情节推进）
  > 他放慢了脚步，把今日誓石认他传承的那一幕，在心里反复嚼。初代……（长段设定推理）……这某域的因果，往后每亮一分，对面的改，便多一分忌惮。（用内心独白倾倒设定伏笔）
- **正确写法（片段）**：
  > 他脚下不停，踩着雪往山上去了。（删内心分梳，动作直接推进）
  > 他回头望了眼洞口——那镇器认了他传承的一幕，还印在眼底。这一程，总算没白来。（长段推理 → 事实 + 一句收束）
  > 设定伏笔交由后续章节的情节/对话自然带出，不在本章用内心一次性倒尽。
- **可固化规则**：
  - **写完一段自问**："这处是靠'他想'推进的，还是靠'事发生'推进的？"若靠想，改事。
  - **内心活动只保留两类**：①情节必需的决策瞬间（"他当即改了主意"）②角色声口下的简短反应（"他心头一紧""他眉头一皱"）。其余长段心理分梳/推演**删**，换成：动作、对话、他人反应、可见事态。
  - 设定伏笔/世界观信息**不靠主角内心推演倾倒**，交给后续情节与对话自然呈现。
  - 与 #007 动作法同源：信息不靠内心标签/机制标签承载，靠可观察的故事；与 #013 互补：穿越设定也不靠"前世想过"补逻辑。

## 案例 #016 — 脱节的信息交代 / 无营养旁白（补内容填感官细节，不填剧情交代）

- **来源**：用户长篇连载项目反馈（修真+规则辩论题材，2026-07-15，某章 通读）
- **现象（用户原话）**：「这种文字出现在这里是为了什么? 凑字数也不是这么凑的啊, 写点环境啊, 长相啊, 衣着啊, 特效啊, 什么东西不能凑? 非要写这种前后毫无关系还毫无营养的东西」
- **根因**：需要补字数/交代信息时，作者用**与当前场景脱节、无感官信息**的旁白把剧情/前因硬塞（如角色已在山上，却写「某管事早先一步把话递到某镇」）。这类交代既不 show（无环境/人物可感），又与当下场景「前后毫无关系」，读者读来是空转补字。
- **错误写法（片段 ≤150 字）**：
  > 他不为那机缘来。某前辈托他照看某门，这话他应下了。某势力要在秘境里跟某门算总账——这话，某商会管事早先一步递到了某镇。（角色在山上，却交代镇上旁人递话；纯信息，零画面）
- **正确写法（片段 ≤150 字）**：
  > 他不为那机缘来。某前辈托他照看某门，这话他应下了。山风顺着领口灌进来，激得他肩背一紧，脚下却更稳了，踩着雪，一步不停地往上。（同处场景内，用环境+动作承载，把「决心」交身体反应呈现）
- **可固化规则**：
  - **补内容填感官，不填交代**：字数不够或需交代信息时，优先写与当前场景相连的**环境 / 长相 / 衣着 / 具体动作 / 特效**，绝不用「谁早先把什么话递到哪」这类脱节的剧情信息硬塞。
  - **旁白须贴着当下场景**：凡写「某人事先得知 / 某处早有风声」，先问「这与角色此刻所处场景有关吗？」无关即删，或改为场景内可感之物（风、雪、路、人影）。
  - 与 #012⑤（机制隐喻硬收）、#014（少内心）、#015（诚实动机≠写说明）同源：皆「作者跳出来替剧情/角色做交代」的反面；本例特指**脱节且无感官的补字交代**。

## 案例 #018 — 做局情节的「零增量催化」与「外部规则降智解」

- **来源**：用户长篇连载项目反馈（修真+规则辩论题材，2026-07-16）
- **现象（抽象）**：冲突段的「发动机」有两个常见烂法——①某角色 A 一直盯着目标 X，作者却让配角 B「指给 A 看 X」，等于让一直盯 X 的人去「看 X」，动作对目标和机制都无增量；②反派作恶时，某世界观机制（如某圣物/天道）自动跳出来惩罚反派，主角毫无作为，反派像被设定而非被主角「做」掉。
- **根因**：①把「做局」写成机械降神式的催化——角色动作不带来任何新信息/局势变化，只负责「触发下一幕」；②弱主角文里，作者嫌主角能力不够，偷偷用外部规则替主角收拾反派，主角能动性被架空，与「弱主角靠脑子」定位冲突。
- **错误写法（片段 ≤150 字）**：
  > 配角抬手指向那少年：「看，就是他。」可那反派从头到尾都死盯着那少年，这一指毫无新意。下一刻，某圣物骤然亮起，自动将反派定在原地——主角站在一旁，什么也没做。（「指」零增量 + 机制自动罚反派，主角空心）
- **正确写法（片段 ≤150 字）**：
  > 主角把满场的恩怨线扫了一遍，最绷的是西边两拨人的死仇线。他踢块碎石种下火，那线崩断，混战漫过反派侧翼——反派阵脚一乱，主角趁空档把目标拉出包围。（主角靠「读线+扯线+借乱」制造真实局势变化，反派是被主角做掉的）
- **可固化规则**：
  - **做局动作须有真实增量**：每个布局动作必须给目标/机制带来角色原本不知道、或局势原本没有的新东西（新信息、新位置、新冲突引爆点）。禁止零增量催化：让一直盯 X 的人「去看 X」、当众「揭穿」早已公开的事实、纯仪式性「指一下」。
  - **避免外部规则降智解**：弱主角文的冲突，优先靠主角能力（洞察/布局/借势/趁乱）制造真实局势变化来解决；某机制若作为情节发动机，须让主角动作对其产生真实触发增量——否则它更适合做「威慑/伏笔」，而非高潮解法。反派须被主角「做」掉，不被设定自动收拾。
  - 与 #015（动机能力相称）、#014（少内心）互补：主角的「做局」本身就是其能力呈现，不需要外部机制代劳。

## 案例 #045 — 爽感场景里作者跳出来解说主角战术（自夸/掰碎爽点/显得主角智商低）

- **来源**：2026-07-19 某章 L33-L37（立查誓对峙）。用户反馈：「我知道你想写爽感, 但是我读起来只感觉到了尴尬,啰嗦,主角智商低」。原文在主角逼对方立誓后，连续用内心独白解说战术：「主角要的正是这光：不费一兵一卒，只把那句敢不敢让天道验的话，砸在对方心口」「这俩不过是棋子上的一层，真正的手在某宗门内…他今日要的不是拿下俩小卒，是借他俩，把那枚印的影子亮给天下看」。
- **现象**：为了让读者 get 到主角多聪明，在爽感/对峙场景里让主角内心或叙事**反复解说自己的计谋**（"我要的正是…""这一招…""不费一兵一卒…""敢的X，不敢的Y"），还替读者把对方反应分析一遍（"他怕是头回干这活，眼底直发虚"）。
- **根因（为什么反而尴尬+显蠢）**：①**自夸**——主角亲口点评自己的招高明，等于王婆卖瓜；②**掰碎爽点**——怕读者看不懂，把爽点揉碎喂到嘴边，读者反被当傻子；③**越解说越显蠢**——计谋本身往往很简单（不敢立誓=心虚），解说越多越显得主角以为这是惊天妙计，实则读者一眼看穿，落差即"智商低"感；④**啰嗦复读**——同一层意思（对方虚了/我赢了）说三遍。
- **错误写法（片段 ≤150 字）**：
  > 他说这话时，腕间光华大盛……主角要的正是这光：不费一兵一卒，只把那句敢不敢让天道验的话，砸在对方心口。敢的，因果清；不敢的，先虚。
  > 主角把为首的迟疑尽收眼底。这为首的怕是头回干这栽赃的活，眼底直发虚。……他今日要的不是拿下俩小卒，是借他俩，把那枚印的影子亮给天下看。
- **正确写法（爽感交给对方的具体反应自己承载；主角不评论自己的招）**：
  > 「不敢立，这案就还有话说。」堂中静了静。为首那年轻弟子张了张嘴，喉结滚了滚，脚下不由往后挪了半寸；他身后的同伴垂着眼，一句没接。
  > （对方的失态=爽点，读者自己会读出"心虚了/主角赢了"；不写"主角要的正是…""这俩不过是棋子…"任何自我解说；主角更深的谋算若必要，留到独处夜思处再展开，不在当场自陈）
- **可固化规则**：
  - 写爽感/对峙场景，写完对方反应后自问：`我有没有再借主角内心/叙事把"这招多妙、对方多虚、我真正目的"讲一遍？` 有就删——爽点由对方反应、结果承载，主角不点评自己的招。
  - 主角的深层谋算（真正目标、幕后黑手）留到**独处思考**处展开，不在当场对着敌人/读者解说；当场解说既是自夸又是过早剧透。
  - "不费一兵一卒 / 我要的正是 / 这一招 / 敢的X不敢的Y / 尽收眼底" 是此类自夸解说的高频信号词，见到就警惕。
  - 与 #017（点题拖尾）、#039（解释尾巴）关系：那两条治"结论后补一句重述"，本例治"整段战术自夸解说"，是爽文场景的专门强化条。

## 案例 #049 — 对话节奏跳级：寒暄分量不足 / 主角显愣头青（撞面直抛诉求、零客套）

- **来源**：2026-07-19 某章 L39-L43 三修（用户「还是太快了，互相寒暄不得各说三两句话啊？主角难道是愣头青人设吗？」）。前两轮已加一句拱手问 + 微一颔首提要求，仍是一来一回、主角零客套直抛诉求，用户判「太快 / 主角像愣头青」。同类错连犯三次，根因是没理解「各说三两句话」= 多轮有来有回。
- **现象**：两个角色公开场合刚碰面，作者为让主角快点入题，只给一句客套甚至零客套，主角一句话把诉求/质问甩出去——读着像愣头青。常见变体：①「加寒暄」只加一句拱手问，仍一来一回就入题；②主角全程零客套，认出人直接提要求/质问；③配角被写成传声筒，只问「你来做什么」无自身语气。
- **根因**：①把「寒暄」理解为「加一句客套话」，没按人设给足社交回合（修真界体面人 / 成名讼师 vs 宗门执法弟子，公开碰面本就有礼数缓冲）；②忽视人设社交分寸——主角是穿越律师，沉稳、懂程序与分寸，不卑不亢，不是愣头青；③配角也该有来有回的自身语气，而非纯递话。
- **错误写法（寒暄不足，主角显愣头青）**：
  > 「主角。」为首的拱了拱手，「今日敝宗在此行事，您怎么也到这台前来了？」
  > 主角微一颔首，站定：「某后生不是某宗门门下。你们拿门规去处置一个门外散修，我得来问个明白。」他目光落在玉盒上，「这草，借我看一眼。」
  > （双方各一句，主角零客套直抛诉求，像愣头青）
- **正确写法（四回合有来有回）**：
  > 「主角。」为首的拱了拱手，「这可真巧，今日敝宗在此办差，竟劳您也到这台前来了。」
  > 主角也拱了拱手还礼：「侥幸。这镇上人多眼杂，台前又热闹，我本想着过来瞧瞧，省得错过了什么要紧事。」
  > 为首的也笑了：「主角客气了，您哪回是真来瞧热闹的。前几回某谷那档子事，您可都在台前站得稳稳的。」
  > 主角摇头失笑：「今日倒真算瞧个热闹。不过既撞上了，有桩事想同贵宗问一句。」他目光落在玉盒上，「某后生不是某宗门门下，这草，借我看一眼。」
  > （双方各 2-3 句，主角先接住社交分寸再落地诉求）
- **可固化规则**：
  - 凡「撞面 → 入题」的对话，先给 1-2 轮**不奔主题**的来回：称呼 / 客套 / 闲笔 / 熟络调侃，让双方有来有回，别一上来直抛诉求。
  - 主角须按人设接住社交分寸：沉稳角色先还礼、接话、缓冲，再落地诉求；不卑不亢，不显愣头青。动笔前先想清楚角色身份（讼师 / 律师 / 老江湖 / 少年）决定开场姿态。
  - 配角也须有自身语气与反应（拱手礼数、熟络调侃、顾虑），不是为主角递话的传声筒；其反应由其身份 / 立场长出。
  - 与 #046（点题 / 强行串线）、#047（描写失真与俗套）关系：本例治「对话节奏跳级 / 寒暄分量」，属对话结构层；对抗性台词长在寒暄缓冲之后（见 某章 L151 诊断「对抗性台词不该在提要求前凭空出现」）。写完自问：这段撞面，双方各说了几句？主角开场像不像这个人设？

## 案例 #075 — 章节内时间线错乱（未发生写成已完成）+ 硬编无冲动对话

- **来源**：2026-08-02 长篇连载项目 某章 实战（记录型配角段）。用户连挑「这个角色为什么要记录谁来看了」「胡编对话/还没开始就录进册里了」。原写「今儿立牌、显像的经过，我都给您录进册里了」——此时显像在数段后才立誓开始，此刻根本没发生。
- **现象**：① 角色台词/动作把**尚未发生**的事描述为「已完成」（如显像未开始就说「已录完显像经过」）；② 为「让角色开口」硬编一句无真实交流冲动的对话（角色此刻没有说话动机，读着假）。
- **根因**：① 信息交代时机错乱——把后段才发生的情节提前当作已完成状态写；② 误以为「配角每场都该有台词」，为凑对话硬造一句，忽视「此时该角色是否有交流冲动」。
- **错误写法**：
  > 某书记抱册立在一侧，笔尖一顿：「主角，今儿立牌、显像的经过，我都给您录进册里了，往后翻这桩案，一字不落。」（显像尚未发生，却说「都录进册里了」；且这句为开口而开口，无交流冲动）
- **正确写法**：
  > 某书记抱一卷册子立在一侧，提笔把立牌的时辰、某卷证摊开的次序，一笔一笔写清。她写得入神，呼出的白气在册页边散开，笔尖在墨里又蘸了蘸，继续落字。（删对话，只留记录动作；记录对象限已发生之事，不碰未发生）
- **可固化规则**：
  - 角色台词/动作**必须服从时间线**：尚未发生的情节（显像/决战/结果）绝不可写成「已完成/已录完/已查清」。交代时机错＝硬伤。
  - 不为「让角色开口」硬编对话：某角色在此刻若无真实交流冲动（无诉求、无疑问、无情绪要传递），就**只写动作不开口**；动作本身（提笔/落字/望/立）已能传递状态。
  - 记录/案卷类动作，记录对象限「已发生」的程序性内容（时辰、次序、布置），不记围观者名姓（非书吏职责），不碰未发生的后续。

## 案例 #079 — 时间词错位（叙事当下的「逢X那日」/ 超前时间词残留）

- **来源**：用户长篇连载项目反馈（修真+规则辩论题材，2026-08-05 某章 修订）
- **现象**：① 叙事当下就是某日（如集日），却写「逢集那日」——「逢X」指未来的 X 日，用在当天自相矛盾；② 已改动的剧情若删了「数日后」类超前时间词，但同章别处仍写「等X数日后踏入」，时间词与已定剧情打架。
- **根因**：把「集日/某日」当成可前置修饰的词，忽略「逢」表未来的语义；局部改剧情忘了同步清时间词。
- **错误写法**：「逢集那日，镇口比平日热闹数倍。」（当天即集日，不能用逢集）/「某崖的公堂张开了网，等主角"数日后"踏入。」（剧情已改，不应残留超前时间词）
- **正确写法**：「集日。镇口比平日热闹数倍，四乡八里的人赶着集往镇上涌……」/「某崖的公堂张开了网，等着主角踏入。」
- **可固化规则**：叙事当下=某日，直接写「X日」，禁写「逢X那日」；全章改动涉及时间线时，grep 残留的「逢X」「数日后」「不久之后」等超前时间词一并清除。

## 案例 #104 — 文本注意力分散（直给平台节奏慢/不好笑的真根因）

- **来源**：2026-08-12 新书《玩家不能跳过的男人》ch001-003 用户反馈（游戏元叙事/搞笑向，番茄类高注意力平台）。用户原话：「节奏慢，不好笑，不是故事情节慢，是文本的注意力分散……番茄上的小说的特点，注意力比较高，其他的描写比较少，可能这样更直给……写史诗作品和网络快餐是不同的风格，甚至有可能是不同的流程方案。」
- **现象**：情节本身是快节奏整人事件（设局→坑人→捞利），读起来却慢、不好笑。检查发现：环境铺陈、外貌铺陈、每个对话都挂动作引导、内心盘算展开写——**大量段落停留在"描写/过渡"，没有推进**（剧情/人设/笑点/爽点），把读者的注意力从笑点上引开了。
- **根因**：用"铺陈型（文学）"写法写"直给型（网文快餐）"内容。平台调性未定，作者默认按文学节奏写：氛围段、动作引导、内心推演都是"文本注意力分散"的来源。番茄类读者注意力贵，每段不推进即流失。
- **错误写法**（铺陈稀释笑点）：
  > 天刚擦黑，巷子深处铺面挂着"谢绝入内"的木牌，门口蹲着个打盹的伙计。花少路过，把斗篷领子拢了拢，红蓝黄三色的羽毛在暮色里晃眼得很，华丽得像王公府上飞出来的鸟儿。他理了理领口，把最后一根翘起来的尾羽按下去，慢悠悠地往城里走。（300字场景/外貌铺垫后才进入事件）
- **正确写法**（直给：一两笔钩子特征即进对话/动作）：
  > 花少从城南那条巷子出来，把袖口上擦不掉的暗色蹭在墙角。他进了听雨轩，往台子上一站，开嗓。头一句还压着，第二句就上了天，像锯子拉锈铁皮。（20字内完成反差+进入笑点）
- **可固化规则**：
  - **开书前定平台/读者调性**（直给型 vs 铺陈型），写入书核与每章 plan「要素①行文风格」标注；史诗/文学允许铺陈，网文快餐必须直给（用户明示：甚至流程方案都不同）。
  - **直给型：每段必须推进**（剧情/人设/笑点/爽点），不设"氛围段"；写后每段自问"推进了什么？删掉会不会更好？"
  - **描写只给钩子性特征**（环境/外貌/动作一两笔）；描写若 2 句内不落回动作/对话/笑点，即删。
  - **对话密度 ≥50%**、短句多、情绪直给；内心戏压成短判断（一两句），不展开推演。
  - 诊断信号："节奏慢/不好笑" 优先怀疑**注意力分散**（描写/过渡稀释），而非情节问题。

## 案例 #105 — 结构/剧情问题用 Edit 修补=错误方案（应整章重写，修改仅处理细节）

- **来源**：2026-08-12 新书《玩家不能跳过的男人》ch001 用户评审。用户原话：「在有结构问题或者剧情问题的时候修改是错误的方案，应该重新生成，修改应该只处理细节的用词，段落分段之类的问题」。
- **现象**：做"清除关注点重构"（结构级改动）后，用局部 Edit 补字数，把"老锤不该进名单+罪名不着调"同一信息补成三遍（三处段落层层重复，违反 #017 同信息重复）。
- **根因**：结构/剧情是整章的组织问题（信息怎么排布、关注点在哪、剧情框架），零散 Edit 改不彻底；补内容时为了凑字数还会复制已有信息，制造新重复/缝合感。
- **错误写法**：结构重构后逐处 Edit 补字数、调逻辑 → 三处重复 + 改不干净。
- **正确写法**：结构/剧情问题 → **整章重写一次到位**；修改（Edit）仅限细节层：用词、段落分段、标点、引号、个别句子。改完 grep 关键词复查同信息是否多处重复。
- **可固化规则**：
  - 先分级：**结构/剧情问题（信息组织/框架/关注点错位/重复）→ 重写；细节问题（用词/分段/标点）→ Edit**。
  - 重写后若需补字数，补的是"新信息/新对话"，不是复制已有段落（grep 复查）。

## 案例 #107 — 搞笑卖点不足：笑点清单未作 plan 前置约束（喜剧文"不够好笑"根因）

- **来源**：2026-08-12 新书《玩家不能跳过的男人》ch001 用户反馈「作为搞笑娱乐为卖点的小说感觉还不够好笑」。ch001 经 v1→v4 四次重写才达标（v4 才加入荒诞升级+弹幕）。用户要求「生成一次到位，不能每章都整一次重写」。
- **现象**：喜剧卖点作品写出来只有"轻幽默"（会心一笑，非拍大腿）：笑点密度 4-6/章、反应温和（听众捂耳）、无荒诞升级、无玩家视角吐槽。
- **根因**：plan 三要素（行文风格/创作重点/情绪）**不含笑点约束**——写之前没定"这章几个笑点、每个什么机制、升级到哪层"，模型只能输出默认轻幽默；标准靠用户反馈逐轮补全 → 每章重写。与 #104（注意力分散）、#106（时间线）同类：**该输入的约束没输入**。
- **错误写法**：plan 只有三要素，写正文时"顺手"埋几个笑点。
- **正确写法**：喜剧/搞笑卖点作品的 plan 必填【笑点清单】：7-10 个/章（每 300-500 字一个），逐个列出 触发场景+笑点机制（荒诞升级/反差/错位/自嗨夸张/弹幕/黑色幽默）+升级层次；并标注 整活位（爆笑点）、弹幕位（玩家/观众吐槽插入点）、自嗨夸张位（主角自我感觉欠揍段）。
- **可固化规则**：
  - 书核明确"搞笑/喜剧"卖点的作品，**每章 plan 必填笑点清单**（技能 SKILL.md「★ 笑点清单」节）。
  - 写完自测：数一遍本章笑点 ≥7 个？强度够不够（反应/自嗨是否夸张到离谱）？不过关即按清单补，不等用户反馈。
  - 升级层次模板：荒诞升级=反应层层离谱（耳塞→灯灭→瓦片掉）；反差=自嗨陶醉 vs 台下空一半；错位=嘴上 A 实际 B；弹幕=读者视角吐槽。

## 案例 #108 — 类型卖点约束未输入 plan（通用：#107 的举一反三）

- **来源**：2026-08-12 新书用户反馈「举一反三，这个问题应该是所有类型的小说都有的，只是我们这本的方向需要的是笑点清单」。
- **现象**：搞笑书不够好笑（#107）、爽文不够爽、悬疑没钩子、感情流没推进、升级流收获稀薄——各类型书的"卖点执行"都靠用户反馈逐轮补标准，每章重写。
- **根因**：#107 只是搞笑特例。本质是通用的：**plan 三要素只约束"怎么写"，不约束"该类型读者的核心期待怎么兑现"**。类型卖点清单（Genre Payoff Checklist）未作前置约束输入。
- **正确写法**：书核确定类型（可复合）→ 每章 plan 必填对应**类型卖点清单**：
  - 搞笑/喜剧 → 笑点清单（7-10/章：触发场景+机制+升级层次+整活位+弹幕位）
  - 爽文/打脸 → 爽点清单（每章 ≥1 个完整闭环：装逼→打脸/升级/捡漏）
  - 悬疑/推理 → 线索清单（显性/隐性线索+误导+反转+伏笔回收表 章X埋→章Y收）
  - 感情流 → 关系节点清单（心动/误会/试探/亲密/危机/和解/告白，每章 ≥1 推进点）
  - 升级/成长 → 收获节点清单（突破/领悟/得宝/升阶，进度表）
  - 恐怖/惊悚 → 惊吓节奏清单（铺垫→爆发→余悸，2-3/章）
  - 职场/博弈 → 博弈节点清单（冲突/试探/反杀/交易，输赢有后果）
- **可固化规则**：
  - 技能 SKILL.md「★ 类型卖点清单」节：按书核类型选清单，每章 plan 必填。
  - 写完自测：按清单逐项数（数量够？强度够？闭环完整？），不过即补，不等用户反馈。
  - 每次反馈暴露的缺失标准 → 前移固化（技能/项目规范），而非只修当前章。

## 案例 #109 — 长篇容量确认失效：宏观数字确认无约束力，必须逐章梗概锁定

- **来源**：2026-08-12 新书《玩家不能跳过的男人》卷1 体量纠错。用户原话：「虽然多次确认了预期的容量，预期的章节数，剧情分配，然后一写正文，还是严重偏离了目标，所以前面那几次关于内容是否够的问答和确认都是没有效果的。」
- **现象**：先后确认"300万字/5卷/60万每卷/15单元/每单元10章"，写 ch001-004 时每个单元却只写 1 章就闭环（ch002 一章救完老锤、ch003 一章投完资、ch004 一章反制完玩家）——卷1 按此节奏只有 15 章≈5.4 万字，距 60 万差 10 倍。确认过三遍的宏观数字毫无约束力。
- **根因**：宏观分层（卷/单元/章的数量和字数）是**抽象数字**，模型写正文时无法把"单元=10章"映射到具体剧情；单元节点里每个单元只设计了 1 个"整人事件"，写一章就闭环。只有**逐章内容梗概**（每章一句话：事件+钩子+所属单元，顺序锁定）才能约束正文不偏——梗概是剧情的最小可执行单元。
- **错误写法**：确认"每单元约10章"后直接写正文 → 单元=单事件 → 一章闭环 → 容量差 10 倍。
- **正确写法**（技能 SKILL.md「阶段零：长篇分层规划」）：
  - 卷→单元→章 三层分层；**单元=事件群**（6-10 个连续小事件+钩子链），不是单事件
  - 动笔前**整卷逐章内容梗概**：章号+一句话（事件+钩子+所属单元），ch001→chN 顺序写全
  - 容量校验以逐章梗概为准（卷字数÷每章字数=章数，逐章分配完才算数）；写正文以梗概为唯一剧情源
  - 防偏离自检：单元写 1-2 章就闭环 → 回梗概重排（拆事件群）；写 1/10 章节时容量进度应对得上 1/10
- **可固化规则**：
  - 长篇小说开书：先分层，再逐章梗概，最后才写正文。**宏观问答确认不算数，逐章梗概落定才算数**。
  - 梗概粒度：每章一句话（事件+钩子+单元），不要写详细 plan（plan 动笔前再展开）。
  - 检测信号：任何"单元/事件一章闭环"或"容量反复确认仍偏离" → 立即回阶段零补逐章梗概。

## 案例 #115 — 补字数稀释主线：内容比重缺「主线≥60-70%」硬约束

- **来源**：用户长篇连载项目反馈（2026-08-20 新书 ch16 审稿后讨论。用户原话：「内容的篇幅……我们需要的是主线的部分至少占60%-70%，然后再夹杂其他的内容，但是因为补充字数之类的步骤，我发现可能会出现补充成主线非常少，其他内容非常多的状态」）。
- **现象**：一章写完字数不足（机检下限 2800），补字数时顺手补「好写的」——插科打诨/氛围描写/配角闲聊/重复已知信息，几轮补下来主线（当章目标推进）只剩一小截，其余全是填充；机检字数过了，读者读完却觉得"这章没干嘛"。
- **根因**：①plan 的「内容比重」只写类型占比（对话40%/动作30%），**没有「主线 vs 填充」的占比硬线**；②补字数动作没有纪律——补的是"容易写的"而非"该有的"；③与 #105（补字数复制已有段落）同源：补字行为脱离主线需求。
- **错误写法**：plan 内容比重写「对话50%+动作30%+氛围20%」，补字数时加两段围观群众闲聊+一段环境描写凑够 2800——主线推进 600 字，填充 2200 字。
- **正确写法**：
  - plan 内容比重**必含「主线 vs 填充」占比**：主线（推进当章目标/长期目标/暗线/清除任务）≥60-70%，填充（插科打诨/氛围/过渡/配角戏）≤30-40%。写正文前先把主线剧情骨架列出来（每段主线要"发生什么+推进什么"），再分配填充。
  - **补字数纪律**：字数不足时，**优先补主线相关的新信息/新对话/新冲突**（主角对目标的下一步动作、暗线新进展、新情报），禁补填充类内容凑数；补完自测主线占比仍 ≥60%。
  - **写完自测**：数一遍主线段 vs 填充段字数占比，主线 <60% 即回补主线内容（不等用户反馈）。
- **可固化规则**：
  - plan 三要素「创作重点」内，**内容比重必须含主线占比数字**（如「主线70%：升职申请推进+暗线一笔；填充30%：酒瓮插科打诨+知音弹幕」），并先列主线剧情骨架再写正文。
  - 补字数=补主线缺口，不是补填充。检测信号：补字数后主线占比反而更低 → 补法错了，删掉填充补主线。
  - 与 #105（补字数复制已有段落）、#107（笑点清单）、#109（逐章梗概锁容量）、#114（对话人物维度）联动：都是「plan 该输入的约束没输入/补动作脱离 plan」。

## 案例 #116 — plan 缺【分段梗概】：剧情顺序与篇幅分配未在 plan 阶段锁定（正文大范围重写根因）

- **来源**：用户长篇连载项目反馈（2026-08-20 新书 ch17/ch18 连续三轮大范围重写后，用户原话：「技能层面也需要更新一下，plan 中需要一个明确的本章分段梗概，明确本章的剧情和行文顺序是 段落1: 情节简介, 篇幅 段落2: 情节简介, 篇幅, 段落3... 我觉得这样可以最大限度的在plan这个环节将故事走向矫正，避免类似现在这样的大范围正文的重新」）。
- **现象**：plan 只有三要素+笑点清单+对话人物维度，但**没有「这场戏按什么顺序发生、每场戏占多少篇幅」的硬约束**。写正文时剧情顺序随写随排，写到哪算哪，章节结构（开头引子过长/主线被配角戏挤占/关键反转位置不对）与 plan 的意图逐渐偏离 → 用户审稿发现问题 → 整章重写（ch17/ch18 均三轮）。
- **根因**：plan 层只有「要素」（怎么写、什么情绪、几个笑点），缺「**结构**」（剧情分几段、每段讲什么、每段占多少篇幅）。要素约束不了「故事的骨骼」；骨骼在正文里自由生长，长歪了只能重写。与 #105（结构问题须整章重写）、#109（逐章梗概锁卷容量）一脉相承：**粒度越细的梗概，约束力越强**。#109 是「卷级逐章梗概」，#116 是「章级分段梗概」。
- **错误写法**：plan 写「三要素：行文风格/创作重点/情绪 + 笑点清单 + 对话人物维度」，正文自由发挥 → 开头铺垫过长、主线戏被挤成小段、反转位置靠后 → 重写。
- **正确写法**：
  - **plan 必含【分段梗概】字段**：把本章按叙事顺序切成 3-8 个段落，每段写「情节简介 + 篇幅占比（或预计字数）」。
  - 例：段落1：混人群装小弟+剑气嫁祸（20%）；段落2：开战+会长上线见解说（20%）；段落3：对峙+卖战歌buff（25%）；段落4：卖回气符+天机阁续命（20%）；段落5：解说收钱+危机苗头（15%）。
  - **分段即锁死剧情顺序**：正文按段落顺序写，段内自由、段序不变；段落之间是「一场戏/一次推进」的天然边界。
  - **篇幅占比即锁死结构比重**：每段篇幅与 #115（主线≥60-70%）联动——主线段加起来 ≥60-70%，填充段 ≤30-40%；段落篇幅写进 plan，正文不得擅自扩缩超 ±10%。
- **可固化规则**：
  - 每章 plan 必填【分段梗概】：段落序号 + 情节简介（一句话）+ 篇幅占比。段落粒度=一场戏/一次推进（3-8 段为宜）。
  - **写正文前，分段梗概是最高优先级的结构约束**：三要素管「怎么写」，分段梗概管「写什么顺序、各占多少」——冲突时以分段梗概为准。
  - **审核 plan 时再审分段梗概**：①顺序是否合理（因果链顺不顺、反转位置对不对）；②主线段篇幅合计是否 ≥60-70%（#115）；③每段是否都能展开成一个「场面」（不能复述成场面=信息型段落，参照 plan 结构自检）；不过关当场改 plan。
  - 正文偏离分段梗概（段序乱/某段篇幅严重超缩）→ 回 plan 校准，不等用户审稿才发现。
  - 与 #105（结构问题重写）、#107（笑点清单）、#109（卷级逐章梗概）、#114（对话人物维度）、#115（主线占比）联动：**plan 的约束粒度 = 卷级梗概(#109) > 章级分段梗概(#116) > 章内要素(#106/#107/#114/#115)**，越细越早锁定，重写成本越低。

## 案例 #117 — 跟踪/直播类角色每次出场位置不变（同质化，位置=信息+喜剧）

- **来源**：用户长篇连载项目反馈（2026-08-22 新书 ch20 审稿：知音出场「蹲在屋檐上」多次复用，用户手改「蹲在井边」并原话：「类似知音这种跟踪戏，每次的出场位置要变才有意思」）。
- **现象**：跟踪/直播类角色（玩家侧元叙事视角的「镜头角色」）每次出场都是同一位置+同一姿势——「蹲在屋檐上/墙头」连用多章。读者看到第三遍就腻，且位置本身的信息量（视角、隐蔽性、被抓包风险）被浪费。
- **根因**：固定角色固定动作=顺手偷懒写法；把跟踪角色当「摄像机支架」而非「场景里的活物」。同族：#005（高频词）、ch17 指令误解模板复读——都是「同一元素原样复用」。
- **错误写法**：ch16/17/18/19 知音每次「蹲在屋檐上，镜头对着他」——四章同位置。
- **正确写法**（ch20 用户示范）：位置每次换——猫墙（ch12）/屋檐（ch17-19）/井边（ch20）/树杈/酒旗后/房梁/人群里……位置可以带新意或喜剧（井边=边打水边看戏、树杈=被鸟啄、酒旗后=半遮面）。
- **可固化规则**：
  1. **跟踪/直播类角色每次出场位置必换**：维护一个「出场位置池」（屋檐/墙头/井边/树杈/旗杆/人群/房梁/马车后……），同角色相邻两次出场不得用同一位置。
  2. **位置=信息+喜剧**：换位置不是无意义挪动——位置可服务剧情（视角/隐蔽性/被识破风险）、可带喜剧（位置本身闹笑话）、可呼应场景（新场景配新位置）。
  3. **固定的是「姿态+功能」，变的是「位置+细节」**：蹲+举镜头（姿态）保留，位置与周边细节（手里拿着啥/被什么遮挡/边上有什么）每次迭代。
  4. 与 #118（弹幕 callback）联动：元叙事层（跟踪/弹幕）是全书的「读者互动层」，这一层最忌复读，最该迭代。

## 案例 #118 — 弹幕/玩梗互动：callback 已立梗（升级呼应），禁原样复读

- **来源**：用户长篇连载项目反馈（2026-08-22 新书 ch20 审稿：①ch19 已用「压黄瓜，管家不刁难我倒立洗头」赌约，ch20 结尾用户手改弹幕「赌！还是倒立洗头！」=callback；②此前 ch20 曾把「赌！一赔三」原样复用（ch16 用过）被用户批。用户原话：「弹幕之类的玩梗互动的情况，可以跟已经用过的相同桥段callback」）。
- **现象**：弹幕/玩家玩梗要么**原样复读**已用梗（「一赔三」两章原词再现，读者「又来了」），要么**每章全新无延续**（梗不积累，追更无记忆点）。两种都浪费。
- **根因**：没区分「callback（同一梗的延续/回响/升级，带新信息）」与「复读（原样照搬）」。#116 同理：复用≠重复，关键在有没有增量。
- **错误写法**：ch16 弹幕「赌！一赔三！」→ ch20 又「赌！一赔三！」——原样复读，零增量。
- **正确写法**（ch20 用户示范）：ch19 立梗「压一根黄瓜，明儿管家不刁难他，我倒立洗头」→ ch20 结尾「赌！还是倒立洗头！」——同一赌梗延续（「还是」=记得上次的赌），老读者会心一笑，追更记忆点形成。
- **可固化规则**：
  1. **玩梗优先 callback 前文已立过的梗**：同一赌约/口头禅/黑话跨章延续，用「还是/又/老规矩」类词点出延续性，形成连续梗（追更记忆点）。这是长篇连载的「梗资产」。
  2. **禁原样复读**：同词同句再现=零增量=腻。复用必须带新信息（升级赌注/换对象/反转/新语境）。
  3. **callback 自带上下文**：老读者会心一笑，但新读者（或忘了的读者）也能从语境读懂，不依赖前文也能成立。
  4. 与 #117（出场位置迭代）联动：元叙事层的所有元素（位置/梗/弹幕）都遵循「可复用、必须迭代」——callback 是迭代的一种（延续性迭代），复读是病。
