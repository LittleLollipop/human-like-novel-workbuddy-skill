# 仿人类小说创作 (Human-Like Novel Writing)

从根源上解决 AI 生成痕迹问题，让 AI 写出具有「人感」的小说。

**当前版本：v2.6.0**（正向注入体系七层全景）

核心思路演进（v2.x）：从「**禁掉 AI 的坏方向**」（负面约束）转向「**给 AI 正确方向的指引**」（正向注入）——模型语体单极化/词汇贫乏/句式单化/描写空泛的根因是**概率稀释**（多义项分摊条件概率）与**register 锁定**（语体序列级特征），负向禁词只是把用词从 top0 切到 top1/top2，时间长了是另一种 AI 味。正解：把「人类常用但模型低概率」的素材在写 plan 时**注入上下文**（attention 拉高生成概率，照抄 chunk 是模型强项）。

---

## 它解决什么问题

AI 生成的小说往往有明显的「AI 味」：

1. **词汇贫乏 / 语体单极化**——朴实则全程朴实，华丽则全程华丽，大量中文词语（尤其歧义大的）被概率稀释边缘化
2. **句式单化**——总是主谓宾直叙 + 「X说」标签 + 短句堆叠，整章一种骨架
3. **描写空泛**——「风很大」「天很冷」，没有具体物象
4. **对话呆板**——一问一答，没潜台词，冲突对话像采访
5. **旁征博引缺失**——不掉书袋、不玩梗，角色没「来历」
6. **节奏均匀**——段落/句式分布过于均匀，没有呼吸
7. **叙事手法缺失**——开场平、动作糊、伏笔不收、反转没铺垫
8. **长篇一致性崩塌**——几十章后设定/称呼/时间线前后矛盾（图数据真源解决）

## 方案总览（v2.6.0 全景）

### 正向注入体系（六层 + 护栏）

| 层 | 管什么 | 素材源 | 频率/用法 |
|----|--------|--------|-----------|
| **词**（血肉） | 词汇人感 | 同义词词林扩展版（77k 词）三级词池：1级=情绪∪感官（人感核心）/2级=其余维度/3级=沾边 | 每约 20 字 1 个 |
| **句式**（骨架） | 句式多样性 | 黄廖《现代汉语》句型/句式/句类/复句（30 式） | 每自然段≤1 种，按需 |
| **引用**（人味） | 旁征博引 | 角色引用素材库（quote_library，可累积） | 每章≥2 处 |
| **技法**（手法） | 修辞/物象/转场/声口 | 陈望道《修辞学发凡》12 格 + 物象库 14 类 + 转场 8 种 + 声口语料 | 修辞每章 2-4 处（调味） |
| **节奏**（呼吸） | 宏观骨架+微观规则 | 救猫咪 15 节拍/故事圈 8 步/三幕/七点/弗莱塔格/英雄之旅 + 微观 7 规则 | 段选体系，章查规则 |
| **叙事手法**（招式） | 对话/开篇/战斗/悬念/场景/喜剧 | 六库 53 条手法（潜台词/黄金三章/动作分解/伏笔/麦基场景/flag打脸…） | 按章节场景选 2-3 条 |
| **负面约束**（护栏） | 禁 AI 痕迹 | 禁词表/破折号非必要全禁/禁句尾堆砌/精确数字模糊化等 | 写前逐条过 |

### 其他核心机制

| 机制 | 解决什么 | 一句话说明 |
|------|----------|------------|
| **词图素材库**（lexicon.axeb） | 素材供给 | 全部素材落一个 axolotl 图库：词 45k + 8 维度 43 锚点 + 句式/修辞/物象/转场/声口/节奏/叙事手法，查询统一走图 |

## 词图素材库（references/word-graph/）

全部写作素材落一个图数据库（axolotl，约 30MB）：

```
词 45k（belongs_to 语义类）+ 8 维度 43 锚点（情绪14/场景9/人物/动作/环境/时令/器物/感官）
句式 30 + 修辞 12（fits 情绪/场景锚点）+ 物象 14 + 转场 8 + 声口 1
节奏 7（救猫咪/故事圈/三幕/七点/弗莱塔格/英雄之旅 + 微观规则）
叙事手法 53（对话/开篇/战斗/悬念/场景/喜剧）
```

**查询工具**（写 plan 时用）：
```bash
python references/word-graph/word_query.py --emotion 温馨,满足 --scene 种田务农 --person 外形 --sense 触感   # 三级词池
python references/word-graph/syntax_query.py --emotion 无奈 --scene 谈判要价                                     # 句式
python references/word-graph/craft_query.py --rhetoric --imagery 冷,穷 --transition --voice --pacing --dialogue # 技法/节奏/叙事手法
```

重建图库：`import_cilin.py`（词林+维度锚点）/ `import_syntax.py`（句式）/ `import_craft.py`（技法）/ `import_pacing.py`（节奏）/ `import_narrative.py`（叙事手法）。

## 关键决策：设定怎么组织？（请先读这一节）

本技能支持两种设定组织方式：**文件模式**（设定写在 markdown 文档里）和**图数据库模式**（设定落在知识图谱中）。

**如果你在 macOS 环境下使用，强烈推荐图数据库模式。**

这不是偏好问题，而是长篇小说场景下**质的不同**：

### 为什么文档组织设定必然撑不住长篇小说

> 随着小说目标长度的增长，所需要的设定将**同步增长**（角色、地点、事件、伏笔、专名、规矩——每多写一章，设定就多一层）。

- 用文档组织设定，创作时为了让模型「知道」设定，只能把**整份/大份设定文档**塞进上下文；
- 小说越长 → 设定越多 → 文档越大 → **与本章无关的设定成为庞大的无效输入**；
- 无效输入挤占上下文、**稀释模型注意力**，模型就开始「选择性遗忘」——这正是长篇写到中后期设定/称呼/时间线前后矛盾的根源。

换句话说：**文档模式的失效不是「模型不够聪明」，而是输入本身出了问题。** 随着目标长度增长，这个问题只会越来越严重，无法靠改 prompt 解决。

### 图数据库模式怎么避免这个问题

- **写前取用**：只把本章相关的实体/关系/字段拉出来（如本章涉及的角色、地点、plan、梗、引用素材库），无关设定不进上下文；
- **写后校验**：正文新出现的设定回流图库，冲突由校验器按规则比对（只输出差异，不做全量 dump）；
- 设定总量无论多大，单章输入始终是「本章需要的子集」，无效输入不随全书长度膨胀。

### 什么时候可以用文件模式

- 短篇/中篇（目标字数少，设定总量小，文档直接全量输入问题不大）；
- 只是试验本技能、不打算写长篇；
- 环境无法运行图数据库工具链。

> 判断标准一句话：**目标长度越长，越应该用图数据库。** 300 万字的长篇用文档组织设定，等于开着行李箱去搬一座山。

## 快速开始

### 安装

**方式一：WorkBuddy 技能市场**（待发布后可用）

**方式二：手动安装**

1. 下载本技能文件夹
2. 放入 `~/.workbuddy/skills/` 目录
3. 重启 WorkBuddy

### 使用（图数据库模式）

```bash
# 1. 初始化项目（建目录结构）
python ~/.workbuddy/skills/human-like-novel/scripts/novel.py init <书名>

# 2. 建设定（阶段一）：世界观/角色/设定点范例/情绪词库（落图库）

# 3. 写章节计划（阶段二，正文前必须）：段内定位/分段梗概/三要素/类型卖点清单
#    + 六层注入位：用词注入位（三级词池）/句式注入位/引用素材位/技法注入位/节奏注入位/叙事手法注入位
#    图库模式：plan 存图库 plan_chXXX 节点（字段清单见 SKILL.md）

# 4. 写正文（阶段三）：一次写一节，每节自检；字数不足=回 plan 加节

# 5. 章节自检（阶段四）：双机检（check_chapter.py + check_error_cases.py）+ selfcheck
python ~/.workbuddy/skills/human-like-novel/scripts/novel.py selfcheck <章号>
```

> 图数据库模式依赖项目级工具链（写前 `fetch_chapter_context.py` 抽上下文、写后双向同步），技能提供规则与字段标准，具体工具脚本由项目自行维护（跨项目通用原则，不固化单书实现进技能）。

## 核心原则（必须遵守）

1. **设定不全，不写正文**
2. **范例库不全，不写正文**
3. **计划不全，不写正文**
4. **六层注入位填全，不写正文**（词/句式/引用/技法/节奏/叙事手法）
5. **负面约束优先于正面要求**（护栏层最后过）
6. **正向注入优先于负面禁止**（给正确方向，不只禁错误方向）
7. **喂 chunk 不喂散词**：素材颗粒度=整词/整句/整范式，模型照抄是强项
8. **情绪×感官是人感核心**（1 级词池）：内部感受×身体接收=同一体验两面
9. **一个场景=一个价值转变**（麦基）：没转变的场景删掉
10. **字数不足=回 plan 加节**，禁正文扩写注水
11. **破折号非必要全禁**，禁句尾堆砌同义情绪词
12. **长篇设定组织优先图数据库**（见「关键决策」节）
13. **error-cases 持续累积**：踩到新坑就追加（#号顺延），机检兜底
