# 仿人类小说创作 (Human-Like Novel Writing)

从根源上解决 AI 生成痕迹问题，让 AI 写出具有「人感」的小说。

内置**轻量级图数据设定真源方案**：以知识图谱（实体-关系-情绪 valence）为设定真源，在正文外维护角色、事件与设定，写前取用、写后校验，解决长篇小说写作的长期一致性问题。

---

## 它解决什么问题

AI 生成的小说往往有明显的「AI 味」，主要体现在：

1. **大量重复描写**（刻意点题）
2. **行文节奏高度统一**，没有变化
3. **用词单调**，缺乏情绪倾向
4. **过于精确的数字**
5. **缺乏旁征博引**（名言/典故/诗词）
6. **缺乏流行文化引用**（网络热梗/搞笑梗）
7. **长篇一致性崩塌**——几十章后设定/称呼/时间线前后矛盾（根源问题，见下文）

---

## 方案总览

| 机制 | 解决什么 | 一句话说明 |
|------|----------|------------|
| 情绪词库 | 用词人感 | 每个角色每种情绪对应专属动词/形容词/句式倾向 |
| 设定点范例库 | 重复点题 | 每个设定点 3-5 个多角度范例，正文只能改编范例 |
| 章节三要素计划 | 节奏单一 | 每章写前必填：行文风格/创作重点/情绪基调 |
| 负面约束系统 | AI 痕迹 | 写前逐条禁止直白点题、精确数字、重复用词等 |
| 引用触发机制 | 旁征博引 | 不在本地建素材库，创作时实时搜索、化用 |
| 流行文化引用 | 时代感 | 按角色身份/场景氛围自然玩梗（非严肃文学） |
| **图数据设定真源** | **长篇一致性** | 设定存知识图谱，写前取用/写后校验，见下节 |

完整工作流见 `SKILL.md`。

## ⭐ 关键决策：设定怎么组织？（请先读这一节）

本技能支持两种设定组织方式：**文件模式**（设定写在 markdown 文档里）和**图数据库模式**（设定落在知识图谱中）。

**如果你在 macOS 环境下使用，强烈推荐图数据库模式。**

这不是偏好问题，而是长篇小说场景下**质的不同**：

### 为什么文档组织设定必然撑不住长篇小说

> 随着小说目标长度的增长，所需要的设定将**同步增长**（角色、地点、事件、伏笔、专名、规矩——每多写一章，设定就多一层）。

- 用文档组织设定，创作时为了让模型「知道」设定，只能把**整份/大份设定文档**塞进上下文；
- 小说越长 → 设定越多 → 文档越大 → **与本章无关的设定成为庞大的无效输入**；
- 无效输入挤占上下文、**稀释模型注意力**，模型就开始「选择性遗忘」——这正是长篇写到中后期设定/称呼/时间线前后矛盾的根源。

换句话说：**文档模式的失效不是「模型不够聪明」，而是输入本身出了问题。** 随着目标长度增长，这个问题只会越来越严重，无法靠改 prompt 解决。

### 图数据库模式怎么避免这个问题

- **写前取用**：只把本章相关的实体/关系/字段拉出来（如本章涉及的角色、地点、plan、梗），无关设定不进上下文；
- **写后校验**：正文新出现的设定回流图库，冲突由校验器按规则比对（只输出差异，不做全量 dump）；
- 设定总量无论多大，单章输入始终是「本章需要的子集」，无效输入不随全书长度膨胀。

### 什么时候可以用文件模式

- 短篇/中篇（目标字数少，设定总量小，文档直接全量输入问题不大）；
- 只是试验本技能、不打算写长篇；
- 环境无法运行图数据库工具链。

> 判断标准一句话：**目标长度越长，越应该用图数据库。** 300 万字的长篇用文档组织设定，等于开着行李箱去搬一座山。

## 快速开始

### 安装

**方式一：WorkBuddy 技能市场**（待发布后可用）

**方式二：手动安装**

1. 下载本技能文件夹
2. 放入 `~/.workbuddy/skills/` 目录
3. 重启 WorkBuddy

### 使用（图数据库模式）

```bash
# 1. 初始化项目（建目录结构）
python ~/.workbuddy/skills/human-like-novel/scripts/novel.py init <书名>

# 2. 建设定（阶段一）：世界观/角色/设定点范例/情绪词库
#    图库模式：设定落图（知识图谱），项目级工具导入

# 3. 写章节计划（阶段二，正文前必须）：三要素 + 类型卖点清单
#    图库模式：plan 存图库 plan_chXXX 节点（字段清单见 SKILL.md）

# 4. 写正文（阶段三）：按 plan 创作，每段过词库/引用/负面约束检查

# 5. 章节自检（阶段四）：机检 AI 痕迹 + 正文↔图库双向同步
python ~/.workbuddy/skills/human-like-novel/scripts/novel.py selfcheck <章号>
```

> 图数据库模式依赖项目级工具链（写前 `fetch_chapter_context.py` 抽上下文、写后双向同步），技能提供规则与字段标准，具体工具脚本由项目自行维护（跨项目通用原则，不固化单书实现进技能）。

## 核心原则（必须遵守）

1. **设定不全，不写正文**
2. **范例库不全，不写正文**
3. **情绪词库不全，不写正文**
4. **计划不全，不写正文**
5. **情绪词库是用词人感的核心**
6. **设定点范例是点题的唯一合法方式**
7. **负面约束优先于正面要求**
8. **模糊数字优先**
9. **情绪必须贯穿全文**
10. **引用触发机制**：不在本地建素材库，创作时实时搜索
11. **引用必须符合角色背景**
12. **流行文化引用必须符合角色身份**
13. **流行文化引用必须符合场景氛围**
14. **流行文化引用必须自然**
15. **长篇设定组织优先图数据库**（见「关键决策」节）：目标长度越长越要用图库，避免文档全量输入的无效输入稀释注意力

| 问题 | 传统 AI 写作 | 使用本技能 |
|------|--------------|------------|
| 重复描写 | ❌ 频繁出现 | ✅ 从范例库选角度，避免重复 |
| 节奏单一 | ❌ 全文匀速 | ✅ 章节计划约束节奏分布 |
| 用词单调 | ❌ 缺乏情绪倾向 | ✅ 情绪词库约束用词 |
| 精确数字 | ❌ 频繁出现 | ✅ 负面约束强制模糊化 |
| 缺乏引用 | ❌ 很少引用 | ✅ 引用触发机制主动搜索 |
| 缺乏流行文化 | ❌ 没有 | ✅ 流行文化引用触发机制 |
| 长篇一致性 | ❌ 中后期崩塌 | ✅ 图数据真源 + 写前取用/写后校验 |
